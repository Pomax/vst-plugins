# A fenced code block draws as a block.
#
# It used to be a stretch of coloured text: the background sat behind the
# glyphs and stopped where the line's words did, so a short line of code was a
# short grey smear rather than part of anything. A block is the whole width of
# every row it covers, the fence rows included.
type:# secondary
type:{ENTER}testing as well
# Enter after the fence marker: that is what closes the fence and leaves the
# caret on the empty line inside it, which is where the code goes.
# Several lines, because one line cannot show whether the rows join up.
type:{ENTER}```js
type:{ENTER}let x = 1;
type:{ENTER}let y = 2;
# `+` is a modifier in the driver's key notation, so it is written as {+}.
type:{ENTER}return x {+} y;
type:{END}{DOWN}{END}
type:{ENTER}and a line after it, to move the caret out of the fence
wait:500
shot:%CACHE%\code-block.png

expect:tabs is 1
# The code is on its own line, inside a fence that closed itself.
expect:notes contain ```js\nlet x = 1;\nlet y = 2;\nreturn x + y;\n```
