# The section strip and the file buttons, in one run: making sections, naming
# the note, Save, Save As, and opening a file back. Dragging sections is
# `dragging-sections`; the built-in explainer is `loading-the-explainer`.
#
# Every file is checked in code the moment its dialog closes, which is where
# each stage is proven: the state the plugin writes is written once, on the
# way out, and by then the file opened last has replaced everything.
#
# A native dialog runs its own message loop, so one opened from inside the
# frame being drawn leaves the frame timer firing into a layout that is already
# under way, and the plugin dies. A dead plugin never reaches its shutdown, so
# this test sees that as no state written at all.
#
# Two things about the keyboard are settled in the first few steps. Nothing is
# clicked before the first line is typed: a note nobody has named opens with
# the keyboard in its name, Enter sends it to the document, and the line lands
# there. Then the note is renamed and another section is made and typed into,
# which says the name field hands the keyboard back.
#
# The name sits mid-toolbar and is its own field: what is typed into it lands
# nowhere else, which the first section's text at the end says. The + button
# follows the last section, so it moves right as sections are added.
# Every section starts as a heading waiting for its name, with the name
# selected. Each one is read off the window before anything is typed, and the
# name typed straight after has to have replaced it: still showing afterwards
# means the selection was not there.
remove:%CACHE%\round-trip.md
type:{ENTER}
showing:Section Title|largest
type:Mix notes
showing:Mix notes|largest
hidden:Section Title
type:{ENTER}levels are close

# Save is Save As until the document has a path, so this is the first dialog.
# The file it wrote is checked in code, and then deleted in code: the name is
# free for the Save As below to write to a file that does not exist, as this
# one did.
#
# Open, Save and Save As are in the menu behind the toolbar's three-dot button.
# The button carries no word: it is the thing drawn left of the Markdown
# source button, and the option is then found by what it says, under the
# menu's Open.
click:beside Markdown source left
press:Save|below Open
dialog:Save
type:%CACHE%\round-trip.md
type:{ENTER}
nodialog:Save
written:%CACHE%\round-trip.md|# Mix notes\n\nlevels are close
remove:%CACHE%\round-trip.md

# A name that fits the window at this size and not at the smaller one it is
# dragged to at the end.
press:project title
type:{END}{BS 40}funky cake with a cherry on top and sprinkles
# The + button carries no word: it is the thing drawn after the last tab, and
# that the click landed is said by the tabs read at the end.
click:beside Mix notes right|smallest
showing:Section Title|largest
type:Drum bus
showing:Drum bus|largest
hidden:Section Title

# Save As. The document has a path by now, which is what makes this a
# different action from the save above rather than the same one twice. Both
# sections, in order.
click:beside Markdown source left
press:Save As
dialog:Save
type:%CACHE%\round-trip.md
type:{ENTER}
nodialog:Save
written:%CACHE%\round-trip.md|# Mix notes\n\nlevels are close\n\n# Drum bus

click:beside Drum bus right|smallest
showing:Section Title|largest
type:Vocal chain
showing:Vocal chain|largest
hidden:Section Title

# Each tab, read in turn. The expectations below take the document the plugin
# wrote and cut it into sections here, so they say nothing about how many tabs
# there are or what each one holds: three sections in one tab would satisfy
# them. Each tab has to show its own text and not its neighbours'.
#
# A section's heading says what its tab says, in bigger letters, so a tab is
# asked for as the smallest of the places its words are, and the heading as
# the words under the tab.
press:Vocal chain|smallest
showing:Vocal chain|largest
hidden:levels are close
press:Drum bus|smallest
showing:Drum bus|largest
hidden:levels are close
press:Mix notes|smallest
showing:levels are close

# Open the two-section file back. It replaces what is open: three sections
# become exactly what that file holds. An open that silently did nothing
# leaves the three, and the expectations below refuse it.
click:beside Markdown source left
press:Open
dialog:Open
type:%CACHE%\round-trip.md
type:{ENTER}
nodialog:Open
# The file holds two sections, so the third tab going is the file having come
# in.
hidden:Vocal chain

cleanup:%CACHE%\round-trip.md

# Both tabs, read rather than typed into. A load that put the whole file in
# one tab satisfies the expectations below. Reading each tab does not: the
# second tab has to show its own line and not the first tab's.
press:Mix notes|smallest
showing:levels are close
press:Drum bus|smallest
showing:Drum bus|largest
hidden:levels are close

# The whole name is on show at this size. The window dragged down to a size
# with no room for it cuts the name to what fits and `...`, and hovering over
# the cut name brings up the whole of it. The name is what is drawn, not what
# is kept, which the expectations below say. The pointer is taken away to the
# empty space under the heading.
showing:sprinkles
dragto:620,420,500
shot:%CACHE%\sections-dragged-small.png
hidden:sprinkles
showing:funky
moveto:funky
showing:sprinkles
moveto:below Drum bus|largest
hidden:sprinkles

# The name is not part of the document, so opening a file leaves it alone:
# the file written here carries it in its frontmatter, and what it holds is
# the two sections the open brought in, in order.
click:beside Markdown source left
press:Save As
dialog:Save
type:%CACHE%\opened.md
type:{ENTER}
nodialog:Save
written:%CACHE%\opened.md|title: funky cake with a cherry on top and sprinkles\n---\n\n# Mix notes\n\nlevels are close\n\n# Drum bus
cleanup:%CACHE%\opened.md

expect:title is funky cake with a cherry on top and sprinkles
expect:sections is 2
expect:section 0 is # Mix notes\n\nlevels are close
expect:section 1 is # Drum bus
