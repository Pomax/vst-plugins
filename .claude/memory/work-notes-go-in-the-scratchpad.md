Anything written to convince myself the work was real goes in a file, not in a
reply. The scratchpad takes it: what changed, which tests were touched, what
was tried. The user gets the outcome, in as many words as the outcome needs.

**Why:** at the end of a task I default to reporting, and the report is for me,
not for them. They said so: *"YOU HAVE A FUCKING INTERNAL FILE SYSTEM, FUCKING
SAVE 'FOR YOU ONLY' SHIT IN THERE AND DON'T FUCKING BOTHER ME WITH IT!"* A list
of what changed makes them read paragraphs to find one word, and the diff
already says all of it.

**How to apply:** finishing a task means saying whether it works. "Done,
`clicking-away-the-caret` passes." If the detail is worth keeping, write it to
`<scratchpad>/notes/` and say nothing about it. Detail reaches the user only
when they ask for it, and then only the part they asked about. Related:
[[plain-language]], [[answer-with-all-of-it]].
